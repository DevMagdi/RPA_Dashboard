# خطة ترقية تجربة المنتج — RPA CoE Control Room v4.1.0 "Private Operations"

## الثوابت التي لا تتغير

- المنتج **غرفة تحكم RPA محايدة للمورّدين** وموجّه للبنوك والمؤسسات الكبيرة.
- كل تثبيت يخدم **جهة واحدة فقط** ويعمل داخل مركز بيانات الجهة / بيئتها المحلية المعزولة.
- لا SaaS، ولا استضافة مشتركة، ولا دعم لتعدد الجهات أو المستأجرين. لا تغيير على حدود RBAC أو سجل التدقيق أو عزل الشبكة.
- تبقى المنصات المتكاملة UiPath وAutomation Anywhere وBlue Prism والموصلات الداخلية خيارات على مستوى التثبيت نفسه.

## توجّه التصميم المقترح

**اسم الاتجاه: Private Operations — وضوح تشغيلي مع فخامة هادئة.** الواجهة الافتراضية Light-first بخلفية فاتحة هادئة وأسطح واضحة، مع Dark mode متكامل كخيار صريح للمناوبات وغرف العمليات الليلية. اللون الأساسي بنفسجي/نيلي تقني ولمسات التركواز للحالة الحية؛ نتجنب ألوان SaaS التسويقية الصارخة وكثرة التدرجات، وتظل الحالات قابلة للتمييز دون الاعتماد على اللون وحده.

قيم Brand وAccent في الجدول هي fallbacks؛ قد يطبّق `BrandingProvider` ألوان التثبيت الموحدة في كلا النمطين.

- الخطوط: `Inter` للإنجليزية و`Cairo` للعربية عند توفرهما محلياً، ثم خطوط النظام؛ لا اعتماد على CDN لأن بعض بيئات البنوك معزولة.
- المسافات على مقياس 4/8px، نصف قطر 12–20px، ظلال خفيفة، أرقام tabular، وLucide للأيقونات.
- أساس المكوّنات: Tailwind مع UI kit داخلي قائم حالياً؛ توحيد واجهاته ومتغيراته على نمط shadcn/ui (CSS variables، حالات focus، variants، وواجهات قابلة لإعادة الاستخدام) بدلاً من استبدال المكوّنات الحساسة دفعة واحدة.
- الحركة قصيرة وهادئة (150–300ms)، مع احترام `prefers-reduced-motion`، ولا تُستخدم لإخفاء انتقالات الحالة أو تأخير الإجراءات.

## هيكل الصفحات المستهدف

1. **Command Center / Dashboard** — حالة الاتصال والوقت، ملخص الأسطول، مؤشرات القيمة، التشغيلات الحية، SLA، حجم التنفيذ، توزيع النتائج، وآخر التشغيلات. الفلاتر قابلة للمشاركة عبر URL وتخصيص اللوحات اختياري.
2. **Processes & ROI** — كتالوج قابل للبحث والفرز، حساسية العملية، SLA، التوقع مقابل التنفيذ، والقيمة المتحققة.
3. **Runs & Jobs** — سجل قابل للتصفية، حالات واضحة، تفاصيل الفشل، إعادة التشغيل/الإيقاف وفق الصلاحيات، ورسوم الاتجاه.
4. **Capacity** — استخدام المشغّلات وضغط الطوابير، مخاطر SLA، توصيات يمكن طلبها أو إقرارها.
5. **Lifecycle & Vault** — مسار Dev → UAT → Prod، صندوق الموافقات، أربعة أعين، وسجل إجراءات بيانات الاعتماد.
6. **Infrastructure / Agents** — صحة موصلات الموردين، نبض الوكلاء، السعة، أوامر التشغيل وتاريخ المزامنة.
7. **Alerts** — قائمة أولويات مع الإقرار والحل وسياق القاعدة.
8. **Governance & Administration** — سجل تدقيق، المستخدمون والأدوار، إعداد الجهة الوحيدة، الصحة والإعدادات. صفحات الإدارة تبقى مخفية/محمية وفق RBAC كما هي.

## أولويات التنفيذ

- **P0:** ثبات المصادقة وRBAC والتدقيق، واجهة Dashboard، حالات الشبكة والتحميل، RTL، عدم حدوث refetch واسع عند تحديث لوحة واحدة.
- **P1:** استكمال تسوية الصفحات التشغيلية، تعميم التنقل بلوحة المفاتيح على التدفقات، وصقل تجارب الجداول والرسوم بعد مراجعة مشغّلي البنك.
- **P2:** تخصيصات إضافية قابلة للاسترجاع، تفاصيل animation/illustration، وفرز/تصفية أكثر تقدماً بعد قياس الاستخدام.

## توصيات تقنية وأهداف قياس

- إبقاء React Query؛ فصل أزمنة freshness حسب طبيعة البيانات، إلغاء الاستعلام عند مغادرة الصفحة، إبطال المفاتيح المتأثرة فقط، وإظهار `cache_hit`/آخر تحديث دون استعلام إضافي.
- إبقاء التحميل الكسول للصفحات، تحميل الرسوم عند ظهورها أو عند الحاجة، تثبيت أحجام حاويات الرسوم، وتجنب إعادة رسم لوحة كاملة بسبب ساعة/عداد.
- استخدام skeleton متطابق مع شكل المحتوى، وempty state يوضح الخطوة التالية، ورسالة خطأ مع إعادة المحاولة ومعرّف الطلب إن توفر.
- القياس المقترح على بيانات ممثلة: LCP أقل من 2.0s على جهاز البنك المستهدف، INP أقل من 200ms، CLS أقل من 0.1، وp95 لواجهة Dashboard أقل من 200ms. هذه أهداف قبول وليست نتائج مفترضة.
- خط تحقق الإطلاق: `pytest` + تغطية backend، اختبارات API وRBAC/Audit، lint/build للواجهة، اختبارات تفاعل RTL/a11y، Playwright visual snapshots على viewport ثابت، وقياس Lighthouse/Web Vitals بعد تشغيل build أمام API مماثل للإنتاج.

### ما تم إنجازه في هذه الدفعة

- **إصلاح العربية من الجذر (خمس طبقات):** أعمدة `NVARCHAR` في SQL Server + سكربت ترقية للقواعد القائمة، رؤوس تنزيل RFC 5987، خط Amiri مضمّن مع تشكيل النص في PDF/Excel، خطوط Cairo/Inter مستضافة ذاتياً داخل التثبيت، وترميز UTF-8 لسجلات الخدمة. لا وجود لأي `؟` أو `????` في أي شاشة أو تصدير.
- **واجهة بريميوم:** Light-first مع Dark كامل، Command Center حي، لوحة أوامر على `Ctrl+K`، نظام تصميم موثّق، حركات ناعمة تحترم `prefers-reduced-motion`، وحالات فراغ/تحميل/خطأ مصقولة.
- **السرعة:** تقسيم الحزم لكل صفحة، تأجيل الرسوم الثقيلة إلى حزمة منفصلة، virtualisation للجداول الكبيرة، gzip، تخزين مؤقت سنة كاملة للأصول ذات التجزئة، تحديث محدود النطاق للاستعلامات، وقياس الأداء السابق موثّق في `docs/TEST_REPORT.md`.
- **العمليات:** صفحة Processes تدعم الجدول والبطاقات مع حفظ اختيار العرض؛ القفز من Command Palette يملأ البحث باسم العملية، كما يمكن إقرار التنبيهات المفتوحة من لوحة الأوامر.
- **الجودة (آخر تحقق):** 352 اختبار Python مع تغطية 81.52% مقابل بوابة 80%، و61 اختبار واجهة ناجحاً، ونجاح `npm run build` و`npm run lint` بلا تحذيرات أو أخطاء. تحذير React عن مفتاح Tabs عولج وأُعيد تشغيل المجموعة كاملة.

هذه الدفعة تضع أساساً مرئياً وتجريبياً قابلاً للتوسع؛ لا تستبدل اختباراً بصرياً فعلياً على أجهزة البنك، ولا تغيّر بنية الأمان أو حدود النشر.
